## Open findings

### 6. Registration fails after creating the account — `prices/views.py` (register view, `send_mail(..., fail_silently=False)`)
No email settings exist, so Django tries a local mail server on port 25; prod runs none. The visitor gets a 500 after the inactive user is saved, the owner is never emailed, and a retry finds the username taken. Tests pass because the test runner uses a fake mailbox.
**Fix:** read `EMAIL_HOST`, `EMAIL_HOST_USER` etc. from the environment and set them on fly; at minimum `fail_silently=True`, log a warning, and check admin for inactive users. Not confirmed in prod logs.

### 7. `/v2/forecasts/?count=` returns the wrong number of runs — `prices/middleware.py` `_canonical_query`
The response cache treats every `/v2/` URL as a chart page and drops unknown params, so all `count` values share one entry (dev: `count=50` then `count=8` both returned 50).
**Fix:** add a `/v2/forecasts/` branch above the `/v2/` catch-all that keys on a clamped `count`.

### 8. Custom history date range has no limit — `prices/views.py` history view
`/v2/history/G/?window=custom&start_date=…&end_date=…` accepts any range; the full range took 13 s and 2.6 MB on dev (over the cache limit).
**Fix:** cap at 60 days (all retained forecast data) in the view and in `_canonical_query`.

### 9. Malformed numbers in URLs cause 500s — `prices/views.py` (v2 chart, ext-forecast), `api/views.py`
`days` is read with a bare `int()`; `/v2/G/?days=abc` returns 500. The history view already handles this.
**Fix:** one small helper that parses, clamps and falls back to the default.

### 10. `reset` ships to prod and wipes everything — `prices/management/commands/reset.py`
Deletes all price history, forecasts and forecast data with no prompt; unreferenced and not in `.dockerignore`.
**Fix:** delete the file.

### 11. No tests for the secret-token checks — `prices/views.py` (`/update`, `/update/status`, Ko-fi summary and webhook)
A refactor that dropped a check would pass every test.
**Fix:** test that `/update` with no/wrong token returns 403, and the Ko-fi webhook with a wrong token returns 403 and records no payment.

### 12. v1 chart page duplicates v2 — `prices/views.py` v1 graph view, `templates/graph.html`, `ForecastForm` in `prices/forms.py`
About 650 lines of a second chart implementation; every pricing or data-source change must be made twice.
**Fix:** check access logs for real v1 traffic, then redirect `/<region>/` to `/v2/<region>/` and delete the view, template and form.

### 13. Unused one-off commands — `add_capacity.py`, `national_agile.py`, `get_local.py`, `export_local.py`
Nothing references them (~130 lines).
**Fix:** delete them.

### 14. Forecast cleanup makes hundreds of queries — `prices/management/commands/update.py` (missing-rows check)
Two counts per forecast, ~500 round trips for ~250 forecasts on every update.
**Fix:** one `annotate(Count(...))` query.

### 15. Leftover code in the update command — `prices/management/commands/update.py`
The "experiment due" value is only logged (the experiment runs only with `--force_experiment`), and an `if True:` wrapper adds an indent level for nothing.
**Fix:** delete both (~10 lines plus the indent).
